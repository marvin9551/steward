# 设计决策

[English](../decisions.md) | 简体中文

这里简短记录塑造本项目的选择。每条都写明备选方案，这样将来改动时是在和"理由"辩论，而不是和代码辩论。

## 1. 用 asyncio，不用线程

**决策：** 整个运行时是 `async`；阻塞型工具通过 `asyncio.to_thread` 放到工作线程。

**理由：** 流式输出、单次工具超时、取消、多渠道路由，本质都是 I/O 等待。`asyncio.wait_for` 一行就能表达超时；线程池则需要队列、哨兵值和一种"放弃任务"的方式。

**代价：** 阻塞操作需要留意（必须 `to_thread`），CPU 密集型工具仍会占住一个 worker。

## 2. 手写 OpenAI SSE，不用 SDK

**决策：** `httpx` + 约 90 行 SSE 与工具调用拼装。

**理由：** 这是一个学习项目，而"线上格式"正是最值得学的东西。按 `index` 拼装 `tool_calls`（参数被拆在多个 `data:` 分片里）是每个 Agent 里最不直观的部分，SDK 会把它藏起来。

**代价：** keep-alive、`[DONE]`、坏 JSON、各家实现差异都要自己处理。生产环境里官方 SDK 是更稳的默认选择；`Provider` 协议意味着换 SDK 不需要动主循环。

## 3. SQLite、只追加、保存模型消息

**决策：** 一张表、JSON payload、不更新、不用 ORM。

**理由：** 对话就是一个有序日志。只追加带来确定性回放、简单备份，以及未来做分支的路径。保存"模型看到的消息"（而非渲染后的文本）让 `history` 成为真正的调试工具。

**否决的备选：** JSONL 文件（查询/过滤不便）、Postgres（单人使用没必要）、ORM（这个体量只增加一层）。

## 4. 按完整 turn 裁剪

**决策：** `context.fit()` 保留能放下的最新若干个 turn，绝不从 turn 中间切。

**理由：** 带 `tool_calls` 的 assistant 消息和它的 `tool` 结果是同一个单元。从中间切开会构造出所有 provider 都会拒绝的请求。相比直接丢弃 turn，优先压缩工具输出——一段 40KB 的文件读取通常没有"导致这次读取的对话"有价值。

**暂缓：** 对被丢弃 turn 做摘要。将来实现时，摘要作为 system 消息插入，磁盘上的日志保持不变。

## 5. 不用 Agent 框架

**决策：** 不引入 LangChain / LlamaIndex 等。

**理由：** 主循环很小，而框架的抽象（chains、runnables、callbacks）会遮蔽这个项目要教的四个步骤。框架提供的集成点——模型适配、工具 schema、重试——这里每个都不到 100 行。

**代价：** 重试、schema 校验、provider 差异都要自己维护。这正是目的，但也是真实的维护成本。

## 6. 工具限定在一个工作目录

**决策：** 所有文件路径都会解析并校验是否位于工作目录内，**所有权限模式都一样**。

**理由：** 用户真正害怕的故障是"助理删错了文件"。单一目录边界容易推理，也容易在系统提示词里讲清楚。

**局限：** shell 命令仍然可以访问工作目录之外。这就是为什么 `workspace-write` 模式下 shell 需要审批，也是 README 明确说"这不是沙箱"的原因。

## 7. 先做审批，暂不做操作系统沙箱

**决策：** `run_shell` 每次调用前询问，除非 `--yes` / `auto_approve`。

**理由：** 笔记本上的个人助理是在用户自己的账号下执行命令；真正的边界需要 bubblewrap（Linux）或 Seatbelt（macOS）以及挂载策略。那是独立阶段；把"子进程环境变量白名单"说成沙箱，比承认它不是更糟。

**下一步：** 类似 `execution/sandbox.py` 的后端，按平台选择，并在启动横幅里明确显示"已沙箱 / 未沙箱"。

## 8. 用事件，不直接 print

**决策：** runner 发出类型化 dataclass；只有 `cli.py` 负责打印。

**理由：** 第二个前端（Web UI 或聊天渠道）的成本就变成一个渲染器，而不是一次重构。测试也能断言事件，而不是抓 stdout。

## 9. 子进程不继承密钥

**决策：** `run_shell` 只传一小份环境变量白名单。

**理由：** 父进程环境里有 API Key。像 `env` 这样的命令或第三方脚本会把它们打印进对话，随后被存进 SQLite 并发给模型。CLI 真正需要的变量可以显式加入白名单。

## 10. 先做 CLI，再做 Web

**决策：** v0 的唯一界面是 REPL。

**理由：** REPL 用约 100 行就能验证主循环、流式输出和审批流程。在事件模型稳定之前做 Web UI 只会返工。Roadmap 在循环不再变动之后再加 SSE 端点和单页界面。
